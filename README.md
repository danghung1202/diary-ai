# Workday Activity Logger v2.0

A headless, command-line interface (CLI) tool for Windows designed to passively record user activity, optimized for **AI summarization**. Unlike standard time-trackers, this tool generates high-fidelity Markdown journals that capture multitasking context (e.g., researching during a meeting) without user intervention.

## Features

- **Dual-Track Logging**: Captures both foreground focus and background context (meetings)
- **Strategy Pattern**: Different data collection approaches for browsers, developer tools, and generic apps
- **Smart Deduplication**: Only logs when activity changes to prevent data bloat
- **Privacy Protection**: Configurable keyword filtering for sensitive information
- **Idle Detection**: Automatically pauses logging during inactivity
- **Markdown Output**: Generates structured tables optimized for LLM ingestion

## System Requirements

- **OS**: Windows 10/11
- **Python**: 3.10 or higher
- **Permissions**: User-level (no admin required for basic functionality)

## Configuration

Edit `config/config.json` to customize behavior:

```json
{
  "polling_interval_seconds": 30,
  "idle_timeout_seconds": 300,
  "output_directory": "logs",
  "blacklist_processes": ["Spotify.exe", "WhatsApp.exe"],
  "meeting_whitelist": ["Teams.exe", "Zoom.exe"],
  "privacy_keywords": ["password", "bank", "confidential"],
  "browser_processes": ["chrome.exe", "msedge.exe"],
  "developer_tools": ["Code.exe", "powershell.exe"],
  "browser_url_timeout_seconds": 0.5
}
```

### Configuration Options

| Option | Description | Default |
|--------|-------------|---------|
| `polling_interval_seconds` | How often to check activity | 30 |
| `idle_timeout_seconds` | Idle time before pausing | 300 (5 min) |
| `output_directory` | Where to save logs | "logs" |
| `blacklist_processes` | Apps to ignore | [] |
| `meeting_whitelist` | Meeting apps to track | ["Teams.exe", "Zoom.exe"] |
| `privacy_keywords` | Keywords to redact | ["password", "bank"] |
| `browser_processes` | Browsers for URL extraction | ["chrome.exe", "msedge.exe"] |
| `developer_tools` | Dev tools for title parsing | ["Code.exe", "powershell.exe"] |
| `browser_url_timeout_seconds` | URL extraction timeout | 0.5 |

## How It Works

### The Polling Loop (Every 30 seconds)

1. **Check Idle**: Is user idle? → Log `[IDLE]` and skip
2. **Get Foreground Window**: Identify active application
3. **Execute Strategy**:
   - **Browsers** (Chrome, Edge): Extract URL from address bar using UI Automation
   - **Developer Tools** (VS Code, Terminal): Extract window title
   - **Other Apps**: Extract process name + title
4. **Scan Background**: Check for meeting apps (Teams, Zoom)
5. **Apply Filters**: Privacy filtering and blacklist
6. **Deduplicate**: Only log if activity changed
7. **Write to Markdown**: Append to daily log file

### Strategy Pattern

The tool uses three strategies for data collection:

#### Strategy A: Browser Deep Inspection
- **Target**: Chrome, Edge, Firefox
- **Action**: UI Automation to extract active URL from address bar
- **Timeout**: 0.5 seconds (fallback to title if timeout)

#### Strategy B: Developer Context
- **Target**: VS Code, Terminal, PowerShell
- **Action**: Parse window title (often contains filename/command)
- **Benefit**: No UI Automation overhead

#### Strategy C: Generic Fallback
- **Target**: All other applications
- **Action**: Process name + window title

## Privacy & Security

### Built-in Privacy Features

1. **Keyword Filtering**: Automatically redacts descriptions containing sensitive keywords
2. **URL Filtering**: Detects sensitive URL patterns (tokens, passwords)
3. **Blacklist**: Exclude specific applications entirely
4. **Local Storage**: All data stays on your machine
5. **No Network**: Tool runs completely offline

### Sensitive Patterns Detected

- `password`, `token=`, `auth=`, `key=`, `secret=`
- User-defined keywords in config

### Example Redaction

```
Before: **Chrome**: Reset Password - [https://bank.com/reset?token=abc123]
After:  **Chrome**: [REDACTED - Privacy]
```

## Troubleshooting

### Common Issues

**Issue**: `ImportError: DLL load failed`
**Solution**: Install/reinstall pywin32:
```bash
pip uninstall pywin32
pip install pywin32
python venv\Scripts\pywin32_postinstall.py -install
```

**Issue**: Browser URLs not being captured
**Solution**: 
- Try running with `--verbose` to see debug info
- Increase `browser_url_timeout_seconds` in config
- URL extraction may not work with all browser versions

**Issue**: High CPU usage
**Solution**:
- Increase `polling_interval_seconds` (default: 30)
- Reduce number of browsers in `browser_processes` config
- Check if UI Automation is timing out frequently

**Issue**: No meeting context captured
**Solution**:
- Verify meeting app executable name matches config
- Use Task Manager to find exact process name (e.g., `Teams.exe` vs `ms-teams.exe`)

## Architecture

```
src/
├── main.py                 # CLI entry point
├── config_manager.py       # Configuration handling
├── window_detector.py      # Window detection (Win32 API)
├── idle_detector.py        # Idle detection (pynput)
├── deduplicator.py         # Activity deduplication
├── privacy_filter.py       # Privacy filtering
├── markdown_writer.py      # Markdown output
├── activity_logger.py      # Main polling loop coordinator
└── strategies/
    ├── base.py            # Abstract strategy
    ├── browser.py         # Browser URL extraction
    ├── developer.py       # Developer tools parsing
    ├── generic.py         # Generic fallback
    └── factory.py         # Strategy selection
```
